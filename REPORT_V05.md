## Методология и обоснование

Expanding-origin сохраняет все доступные прошлые дни; фиксированное
rolling-окно сильнее уменьшило бы короткую обучающую выборку.
Три окна по четыре недели дают одинаковую недельную структуру и
оставляют последний отрезок для проверки. HGB использует исходные
гиперпараметры, без поиска и без ранней остановки на случайном split.
На начало каждого validation-окна ML обучается заново только на прошлом.
Перед TEST выполняется refit на 192 feature-ready днях до 08.08.2025.

Прогноз для t разрешён после закрытия предыдущего торгового дня и
подтверждения полноты загрузки, до открытия t. В offline backtest эти
условия предполагаются: оперативная проверка и исторические времена
доступности не реализованы. Для даты t признаки используют только факты по t−1 включительно;
календарь дня t известен заранее. Веса ML внутри окна фиксированы,
но поступившие вчерашние факты используются в лагах следующего дня.
Поэтому это последовательная оценка однодневных прогнозов, а не прогноз
на 28/60 дней из одной исходной даты. Производственный график
переобучения отдельно не выбирался; длины CV и TEST различаются.

Выбор по pooled OOF WAPE без округления. В каждом окне все три метода
оцениваются на одних датах. Среднее WAPE окон и pooled WAPE различаются
из-за разных объёмов факта. При сумме факта 0 WAPE не определён;
MAE/RMSE при этом доступны. Для нулевой CV выбор по WAPE останавливается.
std — описательный population std (ddof=0), не доверительный интервал.

## Ограничения

- Реальный полный UCI XLSX отсутствует; результаты на нём не получены.
- TEST демо уже раскрыт в v0.4. Независимость входов нового алгоритма
  проверена программно, но перспективно независимой оценки продукта нет.
- Нужны новые данные после фиксации протокола для дальнейшего подтверждения.
- Три зависимых по времени окна недостаточны для годовой сезонности,
  надёжного теста значимости или generalization на другие компании.
- Дневная непрерывность не подтверждает полноту выгрузки. Частично
  загруженный день, закрытие и реальный ноль без внешнего календаря
  неразличимы. Начало/конец исходной выгрузки могут быть неполными.
- `--missing-days zero` — явное допущение пользователя; это не доказательство
  нулевых продаж. Без опции процесс останавливается на дырках.
- Нет меток реальных инцидентов: нельзя заявлять Precision/Recall
  уведомлений, причины аномалий, финансовый убыток или прибыль.
- Совпадение между разными ОС/версиями библиотек и интеграция с реальным
  Telegram-ботом не проверялись. Внешних отправок не было.

## Пять концепций для автора

1. **Forecast origin и доступность признаков:** почему y[t−1] разрешён,
   а заказы дня t недоступны; какое допущение о задержке данных нужно.
2. **Expanding-origin CV и refit:** чем переобучение на границе окна
   отличается от ежедневного обновления лагов и многодневного прогноза.
3. **Holdout и адаптация к тесту:** почему даже небольшой выигрыш HGB
   на TEST не позволяет сменить выбранную по CV медиану.
4. **MAE/RMSE/WAPE:** разные штрафы за ошибки, нулевой знаменатель,
   pooled WAPE против среднего по окнам, разброс против неопределённости.
5. **Точность прогноза и ценность предупреждений:** почему отклонение
   требует проверки качества данных и не устанавливает причину/ущерб.
