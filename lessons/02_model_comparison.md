# Урок 02 — честное сравнение baseline и Gradient Boosting

## Задача

Каждое утро предсказать дневную выручку на один день вперёд. Данные искусственные; ни прибыль, ни потерянную выручку мы по ним не доказываем.

## Три подхода

1. **Seasonal naive**: выручка семь дней назад.
2. **Rolling weekday median**: медиана выручки 7, 14, 21, 28 дней назад.
3. **HistGradientBoostingRegressor**: календарь + лаги + прошлые средние/стандартное отклонение.

Для каждого тестового дня признаки рассчитываются только из истории до этого дня. Мы делаем **последовательный однодневный бэктест**, а не один прогноз сразу на 60 дней.

## Честный эксперимент

- **Train**: обучение ML.
- **Validation**: выбор подхода по WAPE.
- **Test**: однократная проверка зафиксированного выбора.
- ML переобучается на Train+Validation после выбора, не использует Test при обучении.

Для реального внедрения дополнительно потребуются rolling-origin validation, проверка устойчивости к дрейфу и отдельная оценка алертов по размеченным инцидентам.

## Запуск (из корня `business_pulse_ml`)

```powershell
py -m pip install -r requirements.txt
py -m scripts.compare_models --input data/demo/daily_sales.csv --output outputs
```

Открой `outputs/comparison.html`, `outputs/comparison_report.json` и `outputs/comparison_test.csv`.

## Интерпретация результатов демо

На данном фиксированном синтетическом наборе:

| Метод | Validation WAPE | Test WAPE |
|---|---:|---:|
| Семь дней назад | 16,15% | 25,88% |
| Медиана четырёх прошлых недель | **15,77%** | 20,76% |
| Gradient Boosting | 17,10% | **20,74%** |

Победитель **по валидации** — медиана. На тесте ML оказался лучше на **0,02 процентного пункта**, но нельзя выбрать его задним числом по тесту. Разница настолько мала, что оснований утверждать практическое превосходство ML нет.

## Критичные ограничения

- В признаки **не входят** фактические за прогнозируемый день количество чеков, средний чек или расходы на рекламу. Они были бы «знанием будущего».
- Можно использовать **предварительно известный план расходов** или календарь праздников, но в базовой версии их нет в наборе данных.
- WAPE измеряет прогнозную ошибку, **не качество оповещений**. Для алертов нужны размеченные инциденты, оценка precision/recall, задержки и стоимости ошибок.
- Прогноз выручки не даёт причинного прогноза «что будет, если ничего не менять» без дополнительных допущений и дизайна исследования.
