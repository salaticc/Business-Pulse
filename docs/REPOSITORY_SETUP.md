# Перенос Business Pulse в Git

Дата: 11.11.2026. Репозиторий: https://github.com/salaticc/Business-Pulse.
Исходные LICENSE и initial commit владельца сохранены. Архивы импортированы
поверх них; force push и переписывание исходного коммита не применялись.

## Учёт версий

- v0.4.0 — исходный архив MVP; отдельный коммит и аннотированный тег.
- v0.5.0 — окончательный проверенный архив ML Evaluation после уточнения
  времени прогноза; отдельный коммит и аннотированный тег.
- v0.6.0 — Alert Intelligence и организация репозитория; итоговый тег
  указывает на проверенный коммит с правилами разработки и CI.

Это восстановленные этапы, а не вымышленная история исходного написания кода.
Коммиты датированы реальным моментом импорта. Хеш каждого исходного ZIP и
каждого импортированного Python-файла сохранён в
[archive_provenance.json](history/archive_provenance.json).

## Состав

Код, тесты, конфигурации, учебные материалы, синтетические данные,
технические отчёты и журналы проверок перенесены. Исторические результаты
из outputs перемещены в `reports/v0.4.0`, `reports/v0.5.0`, `reports/v0.6.0`.
Новые запуски по-прежнему записывают данные в игнорируемый outputs.
Старые документы сохраняют команды, которые создают такие рабочие результаты.

Локальные пути в опубликованных текстовых журналах заменены на `<workspace>`
или `<temp>`. Числовые результаты и исходные Python-файлы не менялись.
Особые правила .gitattributes сохраняют байты зафиксированных отчётов и
lockfile; новые исходники и документация используют LF.

Окружения, кеши, исходные ZIP, реальное сырьё, секреты и состояние реальной
отправки не входят в Git. Архив retention_bot остаётся отдельным материалом
для будущей интеграции; его содержимое не объявлено проверенным компонентом
Business Pulse и не публиковалось вместе с проектом. Синтетический
monitor_state.json в сохранённом отчёте — учебное свидетельство, не состояние
реального бота.

## Проверки

Проверки перенесённых этапов используют тот же установленный Python 3.14.2
и lockfile, что и разработка проекта. Новая архитектура ML не вводилась.

- v0.4: 12 тестов прошли; сохранились 7 предупреждений Pandas об устаревшем имени.
- v0.5: 53 теста прошли.
- v0.6: 104 теста прошли в новой рабочей копии; числовой результат
  синтетического эксперимента совпал с опубликованным эталоном.
  Журналы — в verification/migration/.
- Отдельно проверяются staged-файлы, типовые шаблоны credentials и отсутствие
  окружений/рабочих данных в индексе. Это ограниченный guard, не обещание
  универсального обнаружения любых секретов.

CI повторяет установку lockfile, guard, тесты, генерацию синтетики,
выбор на validation и регрессию выбранного результата. Actual run status:
https://github.com/salaticc/Business-Pulse/actions/workflows/ci.yml.
Наличие workflow не равно заранее заявленному успеху CI; статус виден в Actions.
Actions закреплены SHA, проверенными по официальным репозиториям
https://github.com/actions/checkout и https://github.com/actions/setup-python.

## Дальнейшая работа

Новые задачи выполняются в этом Git-репозитории по CONTRIBUTING.md.
Изменения — в отдельных ветках, с проверками, PR и записью в CHANGELOG.
VERSION обновляется при выпуске, опубликованные теги не переносятся.
Branch protection административными настройками GitHub не включалась:
правила работы пока закреплены документацией и workflow.

Для проверки нового качества продукта по-прежнему нужны отдельные данные
и протокол, зафиксированный до их просмотра. Публичные синтетические
отчёты используются как регрессионные fixtures, а не независимый тест бизнеса.
